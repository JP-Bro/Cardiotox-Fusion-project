# Review checklist: every finding Dr. Manna has raised, and what now enforces it

Purpose: none of these mistakes may happen twice. Each row says what went wrong, the rule that follows, and the automated guard.
`V:<id>` refers to a check in `scripts/verify_pipeline.py` (the verifier fails if a referenced check does not exist, so this
file cannot go stale). Run the **Before you send anything** routine at the bottom every time.

## A. Working rules (the habits behind the bugs)

| # | Rule | Guard |
|---|---|---|
| P1 | The report describes what the code does. Every sentence in a report or email traces to a file produced by a script; numbers are never typed by hand. | Reports are generated by `scripts/06_make_reports.py`; `V:10`, `V:13c`, `V:15c` compare documents with the data. |
| P2 | Before writing a check, ask what would make it fail. A check that cannot fail is not a check. | `python scripts/test_verifier.py all` injects 9 realistic errors (M1-M9) and requires the verifier to fail each time. |
| P3 | Re-verify what you did not change, not only what was flagged. | `verify_pipeline.py` always runs every check; `python scripts/reproduce_check.py` rebuilds from scratch and compares files. |
| P4 | Always print a metric's baseline next to it (AUC-PR floor = prevalence). AUC-ROC and balanced accuracy come first; flag models that predict one class. | `V:17`, `V:18`; `Degenerate` column in `classical_baselines_comparison.csv`. |
| P5 | Do not hunt for a setting where the number looks better. The primary models are fixed in advance (Morgan-FP RF, L1000 LR, GIN, Transformer); everything else is exploratory. A wide interval honestly reported is a result. | Primary flag in `04_baselines.py`; computed wording in the reports. |
| P6 | Nothing is called "tested", "verified" or "pushed" in an email unless it is true. Email numbers are copied from `results/*.md` after `verify_pipeline.py` passes. | Routine below. |
| P7 | All numbers in one comparison come from one environment; record library versions (random forests differ across scikit-learn / RDKit versions). | `V:16`; `07_train_deep.py report` refuses to refit baselines. |
| P8 | Long jobs write to a log and a completion marker; check the marker, not the process list. A restarted sandbox kills background jobs. | Stage outputs are written per stage. |

## C. Before you send anything (to Dr. Manna or the team)

1. `python scripts/03_rebuild_pipeline.py` and every downstream script that depends on a changed input (04, 05, 07 report), in that order.
2. `python scripts/verify_pipeline.py`, then `python scripts/06_make_reports.py`, then `python scripts/verify_pipeline.py` again. Every check must pass.
3. `python scripts/reproduce_check.py` (clean rebuild matches the committed data) and `python scripts/test_verifier.py all` (the verifier still fails on corrupted data) after any change to `03`, `verify_pipeline.py` or the data.
4. Copy numbers into the email only from `results/*.md`. State limitations (power, environment, name-matched compounds).
5. Commit **and** push before writing "pushed".

## D. References the work is anchored to

- Seal S. et al. (2024). *Insights into Drug Cardiotoxicity from Biological and Chemical Data: The First Public Classifiers for FDA Drug-Induced Cardiotoxicity Rank.* PMID 38300851, PMCID PMC10900289. Prior art on the same DICTrank labels: LINCS L1000 near random (AUC about 0.57), descriptors strong; no scaffold split. Our scaffold-split and negative-result framing is judged against it.
- Gilmer J., Schoenholz S.S., Riley P.F., Vinyals O., Dahl G.E. (2017). *Neural Message Passing for Quantum Chemistry.* ICML 2017 (arXiv:1704.01212). Framework for the message-passing GNN: our GIN is one message-passing instance (sum aggregation, node-feature update, graph readout).
